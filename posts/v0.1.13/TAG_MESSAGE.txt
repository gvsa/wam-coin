------------------------------------------------------------------------------

This release turns ZMQ on, and it is the reason the release exists. A node
can now say the moment it has something — `-zmqpubhashblock`,
`-zmqpubrawblock`, `-zmqpubrawtx`, `-zmqpubsequence` — instead of being asked
every few seconds whether anything happened. An explorer, a pool, a wallet or
something you write yourself can stop polling this chain.

And every archive now carries the libraries it needs — the `wam-coin` node,
the `wam-miner` and the `wam-qt` wallet alike. The wallet had been excused
from the check that enforces that, and the excuse was the fault: unpacked on
a machine that has never compiled anything it stopped on a missing shared
object, which reads as a broken download rather than as a library you lack.

That is the short of it. Nothing here is urgent and nothing here touches
consensus — a node on v0.1.12 is on the same chain and stays on it. The rest
below is for whoever wants it.

WHAT ELSE IS IN IT
------------------

**The check that says a binary carries its libraries now asks what the
loader asks.** It resembled the question before rather than being it, which
is how the wallet passed while being broken. It is also no longer confused by
having nothing to report, and `DEPENDENCIES.txt` has stopped claiming a
dependency list it did not have.

**Packaging says where it died.** `set -e` ends a script without a word about
which line ended it, and a release build that fails silently at two in the
morning is a build nobody can fix before the morning. It now names the step,
and the release build keeps its logs when it fails instead of discarding the
one thing worth reading.

**Packaging survives finding no system Qt**, which was the point of the
change that broke it.

**The pool states its own fee and payout rates, and the pages stop guessing
at them.** Two places described the same numbers and only one of them was
the pool.

**The network hash rate total contains this pool** instead of being estimated
alongside it, so the figure on the page is the figure the chain has.

**`check_nodes_agree.sh` asks each server once** and reads every answer from
that one connection, instead of opening a handshake per question. On three
hosts that was dozens of logins a run.

Check what you downloaded before you run it:

    bash verify_release.sh .

It verifies the signature over SHA256SUMS against the published key and then
every file against SHA256SUMS. A signature covers the files and never the
place they are hosted, so where you fetched them from changes nothing about
what you can check.
