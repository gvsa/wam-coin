Confirmed -- and they are one fault with four faces, not four findings.

daemon.cmd() walks every configured daemon and retries the same call on the
next one when the first throws. sendmany is not exempt. A node that receives
the call, broadcasts, and then loses the connection before answering looks
identical to a node that never got it, so the batch can go out twice with no
attacker involved.

The payout catch block then makes it worse. On any error it deletes
payment:inflight, with a comment saying the call failed so nothing was spent.
That is an assumption the code cannot make -- a timeout is not a refusal -- and
it removes the one record that would have told the next run something
happened, exactly when it is needed.

startupReconcile() itself fails closed and its operator instructions are good.
But start() calls it without await and only logs a rejection, so if that first
Redis read fails the pause is never set and the payment timer is installed
anyway. Your fail-open is real; it is one level above where you placed it.

And the commit is a pipeline(), not a multi(). ioredis pipelines are batched,
not atomic, so the comment claiming that the del surviving implies the
deduction survived does not hold.

One sentence for the root cause: the payout path treats "I do not know" as
"it did not happen".

This is money that moves today, so we are fixing it ourselves now rather than
waiting -- the first two as one patch. The fix separates a definite refusal, a
JSON-RPC error response from the node, from an unknown outcome: timeout,
socket reset, no response at all. The first may clear the intent; the second
must keep it and stop. Money RPCs will not inherit the failover loop, and the
commit becomes a multi().

When it is in, review our fix. You built tests for exactly this behaviour --
exactly-once payout recovery and atomic Redis accounting -- and they are worth
more pointed at our patch than at our old code.

Your repository is scoped correctly: invariants and models, no exploitation
paths, and your SECURITY.md says the right thing. Keep the detail of the two
payout findings out of it until the fix is released.
